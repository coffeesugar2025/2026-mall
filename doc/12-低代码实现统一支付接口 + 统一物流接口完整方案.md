# 低代码实现统一支付接口 + 统一物流接口完整方案
## 一、核心设计思想（低代码适配）
传统方式：每个支付/物流渠道单独写代码、单独维护接口、重复开发鉴权、签名、重试、异常、回调。
低代码统一网关思路：**一层通用适配层 + 渠道配置化插件**，所有第三方渠道只做可视化配置，不写/少写自定义代码，对外输出一套标准统一API。

两大核心目标：
1. **对外标准化**：前端、订单、价格系统只调用一套统一支付/统一物流接口，不用区分支付宝、微信、顺丰、中通；
2. **对内配置化**：新增支付渠道、物流服务商，仅在低代码平台表单配置参数、映射字段，无需发布服务、无需后端改代码。

## 二、整体架构分层（低代码平台标准四层）
```
业务应用层（订单/商城B2B）
        ↓ 统一标准入参、统一返回体
【低代码统一网关服务】统一支付网关 / 统一物流网关
    ├─ 通用能力层（鉴权、加解密、重试、回调、日志、限流、分布式事务）
    └─ 渠道插件适配层（可视化配置映射，少量脚本）
        ↓
各第三方渠道（微信支付、支付宝、顺丰、中通、京东物流等）
```

## 三、第一部分：低代码搭建【统一支付网关】
### 3.1 标准化统一协议（先定标准，低代码只做映射）
#### 1）统一支付下单标准入参（所有渠道共用一套）
```json
{
  "payChannelCode": "WECHAT_PAY/ALI_PAY/UNION_PAY", // 渠道编码
  "outTradeNo": "平台订单号",
  "totalAmount": "金额（分）",
  "subject": "商品标题",
  "buyerId": "客户ID",
  "notifyUrl": "统一回调地址（网关统一接收，分发给业务）",
  "returnUrl": "前端跳转页",
  "payType": "JSAPI/NATIVE/H5/MICROPAY",
  "extraMap": {} // 渠道差异化扩展字段，低代码配置映射
}
```
#### 2）统一返回体（渠道差异全部屏蔽）
```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "payToken": "支付唤起凭证",
    "qrCode": "二维码链接",
    "payUrl": "H5支付链接",
    "tradeStatus": "PENDING"
  }
}
```
#### 3）统一回调标准（支付结果统一格式化）
不管第三方回调字段多乱，网关统一转成：订单号、支付金额、支付时间、渠道流水号、支付状态、手续费。

### 3.2 低代码平台核心数据模型（表单+数据表可视化搭建）
#### 模型1：支付渠道配置表（可视化配置页面）
低代码搭建表单页面，运营可视化新增/编辑支付渠道，存储所有渠道密钥参数：
| 字段          | 说明                                                         |
| ------------- | ------------------------------------------------------------ |
| channelCode   | 渠道唯一编码（WECHAT_PAY_V3）                                |
| channelName   | 渠道名称（微信支付V3）                                       |
| channelType   | 类型：微信/支付宝/银联/对公转账                              |
| enable        | 是否启用开关                                                 |
| configJson    | 渠道私密配置（appid、mchId、私钥、证书路径、加密算法，低代码JSON可视化编辑器维护） |
| signType      | 签名规则：MD5/RSA2/SM2                                       |
| refundSupport | 是否支持退款                                                 |
| limitRule     | 单笔限额、单日限额配置                                       |

#### 模型2：渠道字段映射规则表（低代码核心，实现无代码适配）
解决：第三方接口字段五花八门，通过配置映射转换标准入参 ↔ 第三方参数。
可视化配置项：
- 标准字段名
- 第三方目标字段名
- 转换脚本（低代码JS轻脚本，如金额元转分、时间格式化）
- 默认值、固定常量、是否必填

示例：
标准字段 `totalAmount(分)` → 微信支付接口 `total_fee`，转换脚本：`return Number(val)`；
标准 `outTradeNo` → 支付宝 `out_trade_no`，直接映射无需转换。

#### 模型3：支付订单主表（网关统一流水）
所有支付单统一入库，记录渠道、原始请求、原始返回、映射日志，用于对账。

#### 模型4：退款流水表、回调日志表、渠道异常日志表
低代码自动生成列表页、详情页、导出、查询筛选。

### 3.3 低代码实现核心能力（无需Java后端硬编码）
#### 1）统一API服务（低代码「自定义服务/数据接口」能力）
低代码平台创建公共服务接口：
- `/api/unipay/create` 统一下单
- `/api/unipay/query` 统一查询支付状态
- `/api/unipay/refund` 统一退款
- `/api/unipay/callback/receive` 统一回调接收地址

接口逻辑全部用**平台自带流程引擎**编排：
1. 参数校验（低代码可视化校验规则：金额>0、订单号不能为空）
2. 根据 `payChannelCode` 查询渠道配置、字段映射规则
3. 流程分支：匹配对应渠道映射配置，把标准入参翻译成第三方请求报文
4. 内置HTTP请求组件（低代码原生组件）调用第三方支付接口
5. 第三方返回报文，反向通过映射规则转统一返回体
6. 持久化支付流水、记录完整请求/响应日志
7. 异常分支统一捕获，标准化错误码输出

#### 2）渠道差异化处理：轻量JS脚本（低代码表达式/脚本面板）
复杂逻辑不用写后端服务，在映射规则里嵌入单行/小段JS：
- 金额单位转换（元 ↔ 分）
- 时间格式化（时间戳转yyyyMMddHHmmss）
- RSA签名、MD5加密（平台内置加密函数库）
- 证书读取、报文组装
- 渠道特殊扩展字段拼接

> 只有极特殊渠道（银行对公、复杂证书双向认证）才需要少量自定义组件，90%渠道纯配置完成。

#### 3）统一回调分发（低代码流程引擎自动处理）
1. 第三方全部回调网关统一地址；
2. 流程组件：渠道路由→验签脚本→报文解析映射为标准支付结果；
3. 两种分发模式：
   - 同步：调用业务系统统一回调接口；
   - 异步：低代码内置消息队列组件（Redis/MQ）异步推送，避免超时；
4. 回调失败自动重试（可视化配置重试次数、间隔）。

#### 4）通用能力平台内置，所有支付渠道复用
- 限流、熔断：低代码网关可视化配置QPS限制；
- 分布式锁：防止重复回调、重复支付；
- 日志审计：所有请求自动落地日志表，支持检索导出；
- 资损监控：配置阈值（单笔大额、高频失败）触发钉钉/短信告警；
- 定时任务（低代码XXL-Job可视化面板）：自动对账、自动查询超时订单状态。

### 3.4 新增支付渠道流程（纯配置，不发布版本）
1. 运营后台新增渠道配置，录入商户号、密钥、证书；
2. 进入【字段映射配置页面】，可视化拖拽绑定标准字段与第三方接口字段；
3. 填写签名、加密脚本；
4. 保存启用，前端/订单系统无需改动代码，直接使用该渠道编码调用统一支付接口。

## 四、第二部分：低代码搭建【统一物流网关】
逻辑和统一支付完全同架构，只是业务字段不同。
### 4.1 物流统一标准接口
对外仅3个标准接口：
1. `api/unilogistics/createShipment` 统一创建运单
2. `api/unilogistics/getTrace` 统一查询物流轨迹
3. `api/unilogistics/cancelShipment` 取消运单

统一标准入参屏蔽各快递公司差异：
标准字段：收件人、电话、省市区编码、详细地址、商品重量、体积、订单号、包裹数量、保价金额、上门取件标识。

各快递差异（顺丰额外取件码、中通网点编码、京东仓库编码）全部放到 `extraMap`，通过映射配置处理。

### 4.2 低代码核心数据表
1. **物流渠道配置表**
存储顺丰/中通/圆通/极兔/京东物流API地址、客户编码、秘钥、电子面单模板、月结账号。
2. **物流字段映射规则表**
标准地址字段 ↔ 快递接口地址分段字段映射；轨迹节点映射标准化（已揽收、运输中、派送、签收、异常）。
3. **运单主流水表**
平台统一运单号，关联渠道原始运单号，存储电子面单PDF链接。
4. **物流轨迹日志表**
网关定时拉取/接收快递推送，标准化轨迹存入，业务系统直接读取标准化节点。

### 4.3 低代码特色能力（物流场景专属）
1. **电子面单模板配置化**
低代码可视化拖拽面单打印模板，不同快递公司面单尺寸、打印字段配置保存，统一输出打印文件。
2. **地址标准化转换组件**
内置省市区字典，渠道接口需要拆分province/city/district，通过映射脚本自动拆分。
3. **定时轨迹同步任务**
低代码定时流程：批量查询在途运单→标准化轨迹→入库→推送订单系统更新物流状态。
4. **物流费用自动计算**
渠道配置首重、续重单价，低代码流程自动根据重量计算预估运费，统一返回前端。

## 五、低代码平台通用底层支撑（支付+物流网关共用）
### 5.1 统一鉴权中心（低代码内置身份模块）
所有调用统一支付/物流接口的业务系统（商城、订单、ERP）分配appKey/appSecret，网关统一鉴权，不用每个渠道单独做鉴权。

### 5.2 通用工具组件（平台预制，直接拖拽使用）
- HTTP请求组件：支持POST/GET、JSON/XML、文件上传下载；
- 加密工具：MD5、RSA、AES、SM2国密；
- 日期、金额转换函数库；
- 文件处理：PDF面单生成、图片下载；
- 消息队列：异步回调、异步通知；
- 分布式锁、重试组件、异常捕获分支；
- 定时任务、告警通知（钉钉/短信）。

### 5.3 权限与运维后台（低代码零代码搭建）
1. 渠道配置管理页面：新增、启用、停用、编辑密钥；
2. 字段映射可视化配置页面；
3. 流水查询、对账报表、日志检索；
4. 操作审计日志：谁修改渠道密钥、修改映射规则；
5. 数据隔离：测试渠道/生产渠道分开配置。
