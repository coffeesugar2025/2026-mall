# 前端架构项目经历

```
项目经历
项目名称：ehr企业级人力资源中台前端架构升级
项目周期：202X.X - 202X.X
担任角色：前端架构师
技术栈：Vue 3.4 + Element Plus + Webpack 5 + Qiankun + ECharts + Vite (部分迁移)
项目描述：
负责公司核心人力资源系统（VHR）的前端架构设计与重构。该项目是一个包含复杂组织架构、薪酬计算、考勤审批及员工自助服务的大型单体应用（SPA），并作为主应用通过微前端架构集成多个子业务系统。面临构建速度慢、代码耦合度高、多环境部署复杂及依赖安全等问题，主导了从工程化构建到运行时架构的全面升级。
工作内容：
1.  构建工具链深度优化（Webpack 5）
-主导将构建环境从 Webpack 4 升级至 Webpack 5，利用持久化缓存（cache: { type: 'filesystem' }）和构建性能分析（speed-measure-webpack-plugin），使二次构建速度提升 65%。
-配置 thread-loader 与 esbuild-loader 替代传统 Babel 转译，大幅降低 JS 编译耗时；使用 css-minimizer-webpack-plugin 和 terser-webpack-plugin 进行多线程压缩，优化生产包体积。
-引入 webpack-bundle-analyzer 进行依赖分析，通过 splitChunks 策略抽离公共库，结合 compression-webpack-plugin 实现 Gzip/Brotli 预压缩，减少首屏加载时间。
2.  微前端架构落地（Qiankun）
-基于 qiankun 2.x 搭建微前端基座，制定子应用注册、通信及生命周期管理规范。
-解决 Vue 3 子应用与基座的样式隔离（sandbox: { experimentalStyleIsolation: true }）及 JS 沙箱兼容性问题。
-设计主子应用通用的构建脚本（webpack.prod.conf.js 与 webpack.dev.conf.js），确保各业务团队开发体验一致，实现了 HR 核心模块与绩效、培训等子系统的独立开发与部署。
3.  组件化与 Monorepo 建设
-搭建内部组件库 vhr，抽离高复用业务组件（如薪酬计算器、组织架构树）。
-开发定制化构建脚本（componentBuild.js），支持业务组件的按需打包与发布，统一了公司前端 UI 规范，减少了重复代码量约 30%。
-配置 unplugin-vue-components 和 unplugin-auto-import，实现 Element Plus 组件与 Vue API 的自动按需引入，消除了繁琐的手动 import 声明。
4.  多环境配置与工程化规范
-设计基于 cross-env 和 dotenv 的多环境流转方案，通过 envMode 区分 dev、testing、prod 环境，确保配置与代码分离，消除了因环境差异导致的上线事故。
-搭建 ESLint + Prettier + Husky 的强制代码校验机制，制定 Vue 3 专属编码规范（eslint-plugin-vue），提升了团队代码质量与可读性。
-开发自动化脚本（fetchApi.js, createLangModule.js），实现 Swagger 接口自动生成 TS 声明及多语言文件的自动化合并，减少了人工维护成本。
5.  依赖治理与安全加固
-针对 npm audit 扫描出的高危漏洞进行依赖升级与锁定（package-lock.json），解决 node-forge、loader-utils 等历史遗留安全问题。
-处理 Webpack 5 默认不再自动 polyfill Node 核心模块（如 crypto, stream）的问题，引入 node-polyfill-webpack-plugin 及 crypto-browserify，保证了旧有依赖在浏览器端的正常运行。
-锁定关键依赖版本（如 qiankun 和 element-plus），防止因间接依赖升级导致的不可控 Bug。
6.  性能与体验优化
-引入 mini-css-extract-plugin 抽离 CSS，结合 purgecss-webpack-plugin 剔除未使用的 CSS 样式，显著减小了样式文件体积。
-配置 html-webpack-plugin 动态注入 DLL 或 Vendor 文件，利用浏览器长缓存策略，提升用户二次访问速度。
-针对低版本浏览器兼容性，配置 postcss-preset-env 和 autoprefixer，确保 CSS 属性在各终端的一致性表现。
```
